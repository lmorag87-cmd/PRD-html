## 5. 关键用户旅程

### 5a. IVI — 事件 1：停车后采集

`P挡+车速0` → 状态栏「记录中」→ **SCR-FIND-00** main 自动采集预览 → 质量差则 **DLG-QUALITY** → 用户确认/编辑车位号 → Dock **确认车位** → **SCR-FIND-01** 缩略图入库 → 稳定驻车或用户确认 → 写入 **record_point** + **ingress_path** 绑定 → 车云同步 → 状态栏「可找车」→ 可进入 **SCR-FIND-02**。

**重新记录**：Dock「重新记录」→ **DLG-RERECORD**（禁止末点覆盖记录点、禁止删入库素材）→ 回到 **SCR-FIND-00** 或增量补拍 **SCR-FIND-04**。

### 5b. IVI — 事件 2～3：查看与发起找车

入口（桌面卡片/语音）→ **SCR-FIND-02** → main 地图默认层：记录点 + ingress_path 线 → 点素材 → **SCR-FIND-04** → 点轨迹 → **SCR-FIND-03** 回放 → Dock「导航到车位」调起场内导航或 POI 文字指引 → 多屏时副驾 **SCR-FIND-06** 看素材。

弱网：进 **SCR-FIND-05** 或 **SCR-FIND-02** 顶部离线条，展示上次快照。

### 5c. App — 事件 2～3：离车后找车

推送「车位已记录」→ **PG-FIND-00** → **PG-FIND-01**（锚点=车云 record_point）→ 底 CTA **导航到车位** → **PG-FIND-02** 调起第三方地图（脱敏坐标/deep link）→ 步行用手机 GNSS 相对指引 → **结束找车**。

信息不足 → **PG-FIND-04** 补拍；无网 → **PG-FIND-03** 静态卡。

### 5d. 跨端协同（必填）

| 项 | 规则 |
|----|------|
| **会话模型** | `parking_session_id` 关联 `record_point`、`ingress_path`、`media_index`；车端为采集 **Source of Truth**，经车云同步至 App |
| **同步时机** | 稳定驻车确认、重新记录、路径更新、会话结束/离场 → 推送或 App 轮询；状态栏/App 角标同文案（同步中/已同步/冲突） |
| **锚点** | 地图图钉、App 卡片、第三方导航终点 = **车云 record_point**；禁止 App 用手机当前 GPS 作车位锚点 |
| **冲突** | 车机重新采集后 App 旧卡片显示「已更新」并刷新；未经确认不得用 HPA 末点覆盖记录点 |
| **深链** | `findcar://session/{id}` → **PG-FIND-01**；`action=navigate` → **PG-FIND-02** |
| **离线** | 车机 **SCR-FIND-05**；App **PG-FIND-03** 展示最近一次同步静态信息 + 可选离线地图包 |
| **分工** | 采集/重录/轨迹回放主路径 **仅车机**；App **不重复**环视采集主路径，仅补充补拍与导航跳转 |
