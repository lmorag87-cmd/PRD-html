## 2. 壳层与布局约束（1920×1080）

- **画布**：固定 **1920×1080** 舞台内分区；页外浏览器/演示区深色背景不参与驾驶任务布局语义。
- **状态栏 `status-bar`（深色，`--bar-bg` 类）**  
  - 时间、信号、电量等系统态。  
  - **停车支付上下文**：可选 **会话轻量态**（如「停车中」图标或单色点）、**告警态**（与 PRD 5.3 一致思路：存储/支付异常时状态栏可承载红色感叹号类提示；支付会话级错误优先 **Toast + main 内横幅**，避免状态栏堆砌长文案）。
- **侧栏 `nav`（深色，可选）**  
  - 若本功能挂在 **「影像记录 / 行车相机」大应用** 下：保留现有 **首页 | 预览 | 设置 | …** 导航；当前任务为支付时 **高亮「停车/支付」或通知入口**（具体名称以 UE 为准）。  
  - 若独立 **「停车/支付」** 应用：nav 可收敛为 **当前会话 | 历史记录（可选）** 两项。
- **主区 `main`（浅色 `#eceff4` 类 + 白卡片）**  
  - 承载 **停车卡片、金额、通道状态、扫码区、离场引导**；正文 **约 18px 起跳**，金额 **72–96px 量级**（与 `hmi-prototype` 一致），**思源黑体栈**。
- **Dock（深色，高约 72–88px）**  
  - **左侧**：上下文提示文案（如「优先 ETC」）。  
  - **中部**：**Home**、可选「计费说明」图标入口。  
  - **右侧**：**主操作**（「确认支付」「打开扫码」「重试」「完成」等随屏变化）；次要操作 **「帮助 / 客服」** 放 Dock 或 main 底部次级按钮，避免与主操作并列抢焦点。
- **安全区**：内容区四边默认 **16px** 内边距语义。  
- **触控**：主要按钮热区 **≥ 48×48px** 等效。  
- **模态层级**：全屏扫码 / 对账中 **Modal** > 抽屉 > main 卡片 > Dock。

## 3. 模块与导航（信息架构）

- **一级模块（与 §5 续表对齐）**  
  1. 停车场识别与触发（系统侧为主，车机为 **状态呈现 + 会话建立反馈**）  
  2. 停车事件记录与停车卡片（**车机核心屏 1 主体**）  
  3. 费用实时计算与展示（**屏 1 主区核心**）  
  4. 支付通道判定与降级（**屏 1 动态区 + 屏 2 兜底**）  
  5. 支付执行与状态反馈（**屏 2/3**）  
  6. 离场引导与多终端同步（**屏 3 主区**）
- **入口（与 PRD 对齐）**  
  - **被动**：入场识别成功后 **通知中心** 或 **全屏轻提示** → 进入 **会话卡片**。  
  - **主动**：**「停车/支付」**、影像记录 App 内入口、桌面卡片（以 UE 为准）。  
- **与 Dock 对应**：Dock **Home** 回到桌面不取消会话（会话挂起规则由业务定）；**「停车」图标**可快速回到 **SCR-PAY-01**。

## 5. 关键用户旅程（与壳层交互）

1. **入场 → 会话建立**  
   场端识别 → 车机收事件 → **通知/横幅** → 用户进入 **SCR-PAY-01**：状态栏保持系统态；main 展示 **识别中 → 已入场**；Dock 显示「查看卡片」或默认已展开卡片。

2. **计费刷新 → 1–2s 通道决策**  
   main **应付金额**随场端策略刷新；**进度条或步骤灯** 表示 ETC/无感探测；超时降级 **无感** → 再失败 main 内出现 **「扫码支付」** 主按钮 → 点击进入 **SCR-PAY-02** 或在 **SCR-PAY-01** 内展开扫码区（二选一由 UE 定，本表按独立 **SCR-PAY-02** 规划）。

3. **支付执行 → 双向确认**  
   Dock **「确认」** 或自动扣款触发后，main 显示 **处理中**；成功跳转 **SCR-PAY-03**；失败留在 **SCR-PAY-02** 或 **SCR-PAY-01** 并高亮 **重试 / 换通道**。

4. **离场闭环**  
   **SCR-PAY-03** main 展示 **离场引导**；向场站/车云同步失败时 main **顶部横幅** + Dock **「重试同步」**；出口校验不一致时 **Modal** 以场端为准 + 人工通道说明。

5. **会话取消**  
   驶离识别区或场端作废 → main **会话结束** toast；Dock **「知道了」**；未支付决策 **回滚**（7.5 要求）。

## 6. 与 PRD 差异 / 待澄清

- **§5 续表「停车场找车辅助系统」**：当前 **3 屏未覆盖** AI 视觉记车位、记忆泊车路径、App 联动等；若同一应用内需要 **统一「停车」Hub**，建议在 nav 增加 **「找车」** 与支付并列，另起架构文档。  
- **与影像记录 5.3 关系**：状态栏 **SD 图标 / 红色感叹号** 为 DVR 规范；停车支付是否 **共用状态栏右侧扩展区** 或 **独立会话条**，需 **UE** 冻结避免图标竞争。  
- **语音/方向盘**：7.5 未强制语音支付；若保留，需在 Dock 或全局免打扰策略中声明 **驾驶中交互限制**（法规以项目为准）。  
- **接口字段、签名、对账**：7.5 明确 **集成阶段冻结**；车机 HMI 仅保留 **占位与错误码映射表** 插槽。
