# HMI 信息架构：合作停车场支付闭环（F-01～F-12）

## 1. 文档来源与范围

- **飞书 PRD**：[合作停车场入场—支付—离场](https://baic.feishu.cn/docx/VQX4ddkiboiG4Gxo2V1cAv7DnKf)（token：`VQX4ddkiboiG4Gxo2V1cAv7DnKf`）
- **拉取方式**：`feishuCLI` 目录下 `.\lark-cli.cmd docs +fetch --api-version v2 --as bot`；`--scope section` 锚定 §2～§5（`outline` + 各 `section`）
- **覆盖终端**：**双端** — **IVI 为主交付**；**手机 App** 承担同账号同步、推送与只读/补救入口
- **PRD 锚点**：§3 UC-01/02/03；§4 功能清单；§5 M-01～M-06 / F-01～F-12

**车机负责（主操作）**

- 入场识别反馈、停车卡片、实时计费与冻结态展示
- 通道探测、自动降级、扫码兜底、支付编排与结果
- 悬挂补单、出口闸机不一致强提示、离场引导
- 敏感信息在车机侧的展示与清理

**App 负责（辅）**

- 支付结果/离场引导/会话结束的**推送与只读镜像**
- 同步失败时的手动刷新、弱网下查看最近一次同步快照
- **不重复**车机侧主支付操作（不替代 ETC/无感/车机扫码主路径）

## 2. IVI 壳层与布局（1920×1080）

| 区域 | 视觉 | 职责 |
|------|------|------|
| **状态栏** `status-bar` | 深色 `#1c2128` 类 | 时间、信号、电量；**停车会话轻标**（单色点 +「停车中/待支付/已支付」≤6 字）；不放长文案主操作 |
| **侧栏** `nav`（可选） | 深色 | 挂在「停车/出行」大应用时：**当前会话** \| **历史（可选）**；识别/支付中锁定其它项或二次确认 |
| **主区** `main` | 浅色 `#eceff4` + 白卡片 | 卡片、金额、通道、二维码、引导；正文 **≥18px**，应付金额 **72–96px** |
| **Dock** | 深色，**72–88px** | 左：上下文提示；中：**Home**；右：**屏级主 CTA**（确认支付 / 我已支付 / 完成 / 重试） |

**全局**：安全区 **16px**；触控 **≥48×48px**；字体 **思源黑体族栈**。层级：**全屏强提示** > **支付中蒙层** > **BottomSheet** > **横幅** > main > Dock。

**HTML 原型约定（F-01～F-12）**：本目录 `hmi/*-prototype.html` **统一不绘制** `#stage` 内左侧栏 `nav`（与 SCR-00/02/05 等一致）；跨屏浏览用舞台外 **proto-nav** 全量索引。产品定稿若要求侧栏，须 **整套** 同步加回，禁止仅 SCR-01 单独出现。

| **App** | **PG-PAY-04**：弱网静态卡 +「上次同步 HH:mm」+ **刷新** |

### M-04 支付通道判定

#### F-07 支付通道可用性探测与自动降级

| 项 | 设计 |
|----|------|
| **主区** | **SCR-PAY-01** 内 **通道区** 或展开 **SCR-PAY-03** 通道探测页 |
| **通道列表** | 行项：ETC / 无感 / 扫码 — **推荐标签**、**灰显+原因**（未签约、硬件故障、场端关闭） |
| **决策窗口** | **1–2s 进度条** 或 **步骤灯**（ETC→无感→扫码）；旁 **倒计时**「自动尝试下一方式 Ns」 |
| **耗尽** | 自动导航 **SCR-PAY-06** 扫码兜底（或 SCR-PAY-01 内展开二维码区） |
| **智驾协同** | 扫码兜底态 **顶提示条**（非阻塞）：「缴费宽限期内泊车辅助仍可用」；宽限期耗尽 → **Dialog `DLG-ADAS-EXIT`** 先于智驾退出 |
| **约束** | 禁止并行双扣；探测中 Dock **禁用重复提交** |

#### F-08 手动切换通道与失败码归因

| 项 | 设计 |
|----|------|
| **主屏** | **SCR-PAY-04** 通道选择器（Sheet 或全屏） |
| **列表** | 可选通道 **单选**；不可用项 **禁用+原因**；底部 **二次确认**「切换将重新检测费用」 |
| **失败详情** | **SCR-PAY-08** 或 SCR-PAY-01 内 **折叠区 `FAIL-DETAIL`**：归一文案 + 技术码（小字）+ 建议（换通道/扫码/客服） |
| **Dock** | **「更换支付方式」** 从 SCR-PAY-01/08 进入 SCR-PAY-04 |
| **风控** | 达切换上限 → Toast「已达切换次数上限」 |

### M-05 支付执行与反馈

#### F-09 支付编排、幂等与进度结果展示

| 项 | 设计 |
|----|------|

## 5. 关键用户旅程

### 5a. IVI（UC-01 主路径）

`入场事件 → BANNER-ENTRY → SCR-PAY-00 → SCR-PAY-01（计费刷新）→ SCR-PAY-03 探测 → 成功 SCR-PAY-07 → SCR-PAY-11 → SCR-PAY-12`

- **Dock 主 CTA 随屏**：刷新 → 去支付 → （处理中禁用）→ 离场指引 → 完成

### 5b. App（UC-01/02 辅路径）

`推送（入场/待支付/成功）→ PG-PAY-05 → PG-PAY-01 只读 → 支付完成推送 → PG-PAY-02 → PG-PAY-03`

- **不提供**车机同等「确认 ETC/展示主扫码扣款」按钮，避免双端重复扣款

### 5c. 跨端协同（必填）

| 主题 | 规则 |
|------|------|
| **会话模型** | `sessionId`、`version`、场站名、入场时间、应付金额、支付状态、`txnId`、离场授权态 |
| **Source of Truth** | 计费/闸机/支付结果以 **场端+车云** 为准；车机为支付操作源；App **只读+刷新** |
| **同步时机** | 入场建立、金额变更、支付终态、离场引导、会话关闭 → `SYNC_PUSH`；失败队列退避 |
| **推送深链** | `parking_session` → PG-PAY-01；`payment_success` → PG-PAY-02；`exit_guide` → PG-PAY-03 |
| **冲突** | 车机重新支付/取消 → App 强制刷新；App 不发起支付 |
| **离线** | App 展示 **最近一次同步** 快照（F-04），标注时间；提示「请在车机或出口完成缴费」 |
| **UC-02 多码** | 仅车机 SCR-PAY-06；App 不展示可扫主码（防误用非缴费码） |
| **UC-03 悬挂** | 车机 SCR-PAY-09/10 为主；App PG-PAY-04 仅状态查询 |
